“It works in staging.”

The most expensive sentence in software. Production is missing an env var, runs an older Node, talks to a different Postgres, or skips the migration step. Nobody notices until it breaks.

Parmenides held that what truly is, is one and unchanging, and that change is an illusion of mortal opinion.

Your environments are supposed to be one thing too. This skill finds where they are not.

The two roads.

In his poem, a goddess shows him two roads: the Way of Truth and the Way of Opinion. His report follows them. This is a real, unedited run on a demo app with eight drifts planted on purpose. It found all eight.

The Way of Truth

What it compares.

  1. Env var keys

    Present in one environment, missing in another. A key missing in prod is the classic outage.

  2. Runtimes

    .nvmrc, .python-version, .tool-versions, engines, Dockerfile FROM.

  3. Dependencies

    Lockfiles and pins that differ between environments, services or branches.

  4. Images

    Database, cache and queue versions, and anything on latest.

  5. Behavior

    Feature flags, timeouts, retries, pool sizes, CORS, cookie and TLS settings.

  6. Infrastructure

    Terraform, Kubernetes overlays, Helm values, Pulumi stacks.

  7. Pipelines

    Steps that run before one deploy and are skipped before another.

It finds your environments in per-environment files (.env.production, config/staging.yml, docker-compose.prod.yml, values-prod.yaml, prod.tfvars) or in branches, like staging against main.

Secrets stay
under the floor.

It compares keys, not values. A secret only ever shows up as same, differs or missing. If a real secret is committed to the repo, it flags that, without printing it.

STRIPE_SECRET_KEYdiffers
SESSION_SECRETdiffers
DATABASE_URLhost differs
STRIPE_WEBHOOK_SECRETmissing in prod

Some differences
are meant to be.

URLs, replica counts and log levels should differ. List them in a .parmenides.yml and they stop counting as drift. A key that's missing still counts.

# .parmenides.yml
expected:
  - LOG_LEVEL
  - "*_URL"
  - replicas

Install it.

Installs the skill into every agent on your machine. Needs Node.js 22 or newer; on older versions use Script.

$ npx skills add senavoh/parmenides

Inside Claude Code, add the marketplace, then install the plugin.

/plugin marketplace add senavoh/parmenides
/plugin install parmenides@parmenides

Copies the skill into every agent folder it finds. Read the script first.

$ curl -fsSL https://raw.githubusercontent.com/senavoh/parmenides/main/install.sh | sh

Clone the repo and copy the skill into your agent's skills folder. This path is for Claude Code.

$ git clone https://github.com/senavoh/parmenides
$ cp -r parmenides/skills/parmenides ~/.claude/skills/

Then open a project and ask

“Is staging the same as prod?”

Or “compare my environments”, or “what's different between the staging and main branches?”

Questions.

Will it change anything?

No. It reads files and writes nothing unless you ask it to save the report as PARMENIDES.md. It never runs deploys or touches a real environment.

Does it see my secrets?

It reads your env files to compare keys, the way your agent reads any file. It never prints a secret value: only same, differs or missing.

Is it free?

Yes. Open source under the MIT license, no API key. The only cost is your agent's own usage.

Which agents does it work with?

Claude Code, Codex, Cursor, Gemini CLI, OpenCode, and any agent that reads SKILL.md files.

Can it compare live environments?

Not yet. Today it compares what's in the repo: files and branches. Read-only checks of live cloud environments are on the roadmap.

Who was Parmenides?

A Greek philosopher from Elea, in southern Italy, born around 515 BC. His one surviving work is a poem, On Nature, where a goddess teaches him that what is, is one and unchanging.
